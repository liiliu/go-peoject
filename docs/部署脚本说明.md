# 部署脚本说明

## 📋 脚本概览

| 脚本 | 用途 | 位置 |
|------|------|------|
| **yun-test.sh** | 测试环境一键部署 | 项目根目录 |
| **yun-prod.sh** | 生产环境一键部署 | 项目根目录 |
| **restart.sh** | 服务管理脚本 | 项目根目录 |

---

## 🚀 一键部署脚本

### yun-test.sh（测试环境）

**功能流程**：
1. 编译 Linux 版本二进制文件
2. 上传到测试服务器
3. 备份旧版本
4. 替换新版本
5. 重启服务
6. 健康检查

**使用方法**：

```bash
bash yun-test.sh
```

**配置参数**（脚本顶部）：

```bash
# 服务器配置
SSH_USER="root"
SSH_HOST="192.168.1.100"    # 测试服务器 IP
SSH_PORT="22"

# 项目配置
REMOTE_DIR="/data/server/your_project"
LOCAL_BIN="server"
```

---

### yun-prod.sh（生产环境）

**与测试环境的区别**：
- ✅ 需要二次确认
- ✅ 更详细的日志
- ✅ 更严格的健康检查

**使用方法**：

```bash
bash yun-prod.sh
```

部署过程中会提示：
```
========================================
警告：即将部署到生产环境！
服务器：192.168.1.200
项目：/data/server/your_project
========================================
确认继续？(yes/no):
```

输入 `yes` 确认后继续部署。

## 🔧 服务管理脚本（restart.sh）

### 基本命令

#### 启动服务

```bash
# 部署并启动所有服务
bash restart.sh start

# 仅启动服务（不重新编译部署）
bash restart.sh run

# 重启所有服务
bash restart.sh restart
```

#### 停止服务

```bash
# 停止所有服务
bash restart.sh stop
```

#### 查看状态

```bash
# 查看服务状态和资源占用
bash restart.sh status
```

输出示例：
```
================================================================================
服务状态
================================================================================
API 服务         [运行中] PID: 12345  CPU: 2.3%  内存: 45.6MB  运行时间: 2h 30m
JOB 服务         [运行中] PID: 12346  CPU: 0.5%  内存: 32.1MB  运行时间: 2h 30m
================================================================================
```

---

### 日志管理

#### 查看日志

```bash
# 查看 API 服务最近 100 行日志
bash restart.sh logs api 100

# 查看 JOB 服务最近 50 行日志
bash restart.sh logs job 50

# 实时跟踪日志
tail -f logs/api.log
```

#### 清理日志

```bash
# 清理过大的日志文件（超过 100MB）
bash restart.sh clean
```

---

### 监控模式

```bash
# 进入监控模式（每10秒检查一次，异常时自动重启）
bash restart.sh watch
```

监控模式会：
- ✅ 每 10 秒检查服务状态
- ✅ 发现异常自动重启服务
- ✅ 记录重启日志
- ✅ 按 Ctrl+C 退出监控

## 📝 脚本配置

### restart.sh 配置参数

在脚本顶部的配置区域：

```bash
# ============ 配置区域 ============

# 项目部署目录
PROJECT_DIR="/data/server/your_project"

# 服务二进制文件名
SERVER_BIN="server"

# 需要启动的服务列表（多个服务用空格分隔）
SERVICES="api job"

# 日志目录
LOG_DIR="${PROJECT_DIR}/logs"

# 日志大小限制（MB）
LOG_SIZE_LIMIT=100
```

## 🎯 使用场景

### 场景 1：首次部署

```bash
# 1. 本地编译并部署到测试环境
bash yun-test.sh

# 2. 登录服务器检查
ssh user@server
cd /data/server/your_project
bash restart.sh status

# 3. 查看日志
bash restart.sh logs api 50
```

### 场景 2：代码更新

```bash
# 1. 提交代码
git commit -am "Update features"

# 2. 部署到测试环境
bash yun-test.sh

# 3. 测试通过后部署到生产
bash yun-prod.sh
```

### 场景 3：服务异常

```bash
# 1. 查看服务状态
bash restart.sh status

# 2. 查看错误日志
bash restart.sh logs api 100

# 3. 重启服务
bash restart.sh restart
```

### 场景 4：添加新服务

**修改 restart.sh**：

```bash
# 修改服务列表
SERVICES="api job worker"  # 添加 worker 服务
```

**部署**：

```bash
bash yun-test.sh
```

## ⚠️ 注意事项

### 1. SSH 免密登录

首次使用前需要配置 SSH 密钥：

```bash
# 生成密钥
ssh-keygen -t rsa

# 上传公钥到服务器
ssh-copy-id user@server
```

### 2. 服务器目录权限

确保部署目录有写入权限：

```bash
chmod 755 /data/server/your_project
```

### 3. 防火墙配置

确保服务端口开放：

```bash
# 开放 8080 端口
firewall-cmd --add-port=8080/tcp --permanent
firewall-cmd --reload
```

### 4. 备份策略

部署脚本会自动备份，保留最近 5 个版本：

```
backup/
├── server.20251016_140501
├── server.20251016_140502
├── server.20251016_140503
├── server.20251016_140504
└── server.20251016_140505
```

超过 5 个会自动删除最旧的。

## 🔍 故障排查

### 部署失败

```bash
# 检查 SSH 连接
ssh -vvv user@server

# 检查磁盘空间
df -h

# 检查网络
ping server
```

### 服务启动失败

```bash
# 查看详细日志
tail -n 100 logs/api.log

# 手动启动测试
./server api

# 检查端口占用
netstat -tlnp | grep 8080
```

### 健康检查失败

```bash
# 手动测试健康检查接口
curl http://localhost:8080/v1/health

# 检查数据库连接
mysql -h localhost -u root -p

# 检查 Redis 连接
redis-cli ping
```

## 💡 最佳实践

1. **先测试后生产** - 总是先部署到测试环境

3. **备份数据** - 生产环境部署前备份数据库
4. **灰度发布** - 重要更新考虑分批部署
5. **监控告警** - 配置服务监控和告警
